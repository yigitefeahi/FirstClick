# Edtech Sector Playbook

This file gains importance when the **edtech** sector package is selected in FirstClick analysis. Each section can be retrieved as an independent RAG piece. No fabricated statistics or definitive regulatory provisions are written.

## Scope and Business Model Context (edtech)

Edtech may include B2C courses, B2B corporate learning, language, exam prep, tutoring, or LMS. Revenue can come from subscriptions, course sales, seat licenses, or marketplace commissions. In FirstClick edtech analysis, the learning outcome promise must align with the first session experience. Claims like 'job guarantee / score guarantee' without evidence generate skeptical distrust — employment rates must not be fabricated. For products aimed at children, a parent account and KVKK (Turkish data protection) signal are expected; no legal provision is given.

This playbook customizes general SaaS rules when selected in the FirstClick sector package. The analyst does not fabricate numerical sector benchmarks; relies on product corpus evidence. Heuristics are clearly marked and score justifications are written with citations.

## First Impression Questions (edtech)

What is being taught and to whom? Is there level placement? How soon does the first lesson start? How is progress displayed? Is the instructor live or recorded? What does the certificate mean? Is the price periodic? Busy-professionals want short sessions; students want price and social proof; skepticals want job guarantee; non-technicals want jargon-free curriculum.

If category and outcome sentences cannot be established in the first 10 seconds, clarityScore is suppressed. CTA hierarchy should have a single primary action. If there is social proof, it should be specific; generic logo walls may be weak.

## Onboarding and Activation (edtech)

Activation: completing the first lesson, first quiz, first assignment submission, first live class participation, first learning path selection. Long placement tests delay the aha moment; skip or short diagnostic is a heuristic. An empty dashboard should offer a recommended path instead of 'no courses'. In corporate edtech, admin provisioning vs learner self-serve should be separated.

Name the activation event in product language. If the empty state does not show the next step, onboardingRisk increases. Mandatory integration/form chains should be separate events on the timeline. If there is skip or progressive disclosure, note it as a positive signal.

## Price, Trust, and Compliance Warnings (edtech)

Subscription, per-course, and family plan should be clear. 'Unlimited access' should not contradict an exception list. If there is a refund/cancellation text, check for consistency. If certificate is a hidden paid add-on, distrust. Child data and parental consent should be explained transparently.

Unsupported percentages and guarantee claims violate citation discipline. If the KVKK/privacy link and the UI permission/purpose text contradict, trust↓. For enterprise promises, look for SSO/audit/role signals; if absent, note as missing signal, do not give a legal verdict.

## Persona Reactions (edtech)

Student: price+trial. Busy-professional: microlearning. Skeptical: exaggerated career promise. Non-technical: level uncertainty. First-timer: 'Can I succeed?' — first success moment is critical. Teacher/admin: reporting and class management.

Corpus citation is mandatory in persona reactions. Do not force personas that do not fit the product. ToughQuestions should be concrete and answerable; no insults or speculation.

## Drop-off Timeline Patterns (edtech)

Landing unclear level → long placement → paywall before first lesson → live class technical friction → week-1 silence. Stages: Placement, First lesson, Practice, Paywall.

Add ratio and percentage. Write stage name + friction type (confusion/friction/distrust). Week-1 silence can be an early qualitative signal.

## Evidence to Seek in Corpus (edtech)

Curriculum, level, trial, certificate definition, instructor profile, progress UI, class/admin, child/parent, refund, KVKK. Contradiction: job guarantee vs footnote; start in 5 minutes vs 40 min test.

If no evidence, say 'not found'. For contradiction findings, place two citations side by side. Do not import evidence from competitor sites.

## FirstClick Score Effects (edtech)

Clarity: what is being learned. Adoption: speed of first lesson. OnboardingRisk: long test/mandatory account. Trust: guarantee language and child data. Paywall before aha lowers adoption.

Justify the score with a one-sentence slogan. Separate clarityScore, adoptionScore, onboardingRisk, and trust effects. Promise-UI contradiction can affect multiple scores together.

## Action Checklist (edtech)

1) Level+outcome in hero. 2) Open first lesson early. 3) Shorten/skip placement. 4) Make progress visible. 5) Link guarantee language to evidence or remove. 6) Move paywall after first success. 7) Write certificate definition. 8) Separate admin/learner paths. 9) Child privacy. 10) Cite.

Recommendations should be actionable and prioritizable. Each recommendation should be linked to a finding. Instead of general advice like 'do better', write a concrete UI/text change.

## Learning Design Signals (edtech)

In FirstClick edtech analysis, the curriculum promise must align with the first lesson experience. If it says "project-based learning" but only offers a video watch list, there is a promise-UI contradiction. If the progress bar shows a percentage, what does the percentage measure — time or mastery — if unclear, non-technical confusion is noted. The distinction between "completion" and "proficiency" certificates is critical for skepticals; do not add unsupported employment rates.

For live class products, no-show and recording (replay) policies are sought in the corpus. If absent, note as missing signal. If the teacher panel promise is mixed with the B2C course interface, clarity drops. FirstClick does not measure learning effectiveness; it measures experience consistency.

## Corporate Edtech Special Path (edtech)

Seat license, SSO, assignment, and completion reports are part of B2B edtech activation. The "build an academy" promise contradicts a mere catalog list. Admin onboarding should be a separate timeline event from learner onboarding. For price-sensitive SMEs, minimum seat pressure generates objections; hidden annual only is distrust. Analyst does not fabricate L&D ROI percentages.

## Child and Family Edtech Warnings (edtech)

For child accounts, parent gate, data minimization, and ad limits should be explained transparently. "Safe" slogan alone is not proof of trust. FirstClick does not make legal compliance decisions; looks for purpose text and control UI. Do not mix student persona with child persona.

## Level Placement and First Lesson Tension (edtech)

In edtech products, placement tests often contradict the "start learning immediately" promise. FirstClick analyst reads test length, skip presence, and how the result links to the curriculum. A mandatory 40-question test creates friction for busy-professionals and students; if fully skippable but resultless, it does not provide clarity. Heuristic: short diagnostic (few questions) + immediate first micro-lesson + deeper placement if desired. Activation should be "first lesson/quiz completed," not "account created."

In live class models, if calendar, time zone, recording (replay), and no-show policy are absent in the corpus, note as missing signal. If there is a replay promise but no replay UI, it's a contradiction. If teacher and student panels are mixed in the same IA, role confusion occurs. In corporate edtech, admin assignment report does not replace learner aha; separate the two activations.

## Evidence, Certificate, and Career Claims (edtech)

Phrases like "job guarantee," "score guarantee," or "X% of graduates found jobs" are high distrust candidates in FirstClick; if the percentage is not supported by corpus methodology, mark as fabricated. Certificate must clearly state if it is for "participation" or "proficiency." If there is no instructor profile promise, social proof is weak. If Q&A or assignment feedback is part of the aha, it should be visible in the empty state.

In child/family products, parent gate, data minimization, and ad limits should be explained transparently. "Safe" slogan alone is not evidence. Analyst does not give definitive COPPA/KVKK rulings; looks for control UI and purpose text. In pricing, family plan, periodic campaign, and refund language are critical for price-sensitive users; if paywall is before the first lesson, adoption↓.
