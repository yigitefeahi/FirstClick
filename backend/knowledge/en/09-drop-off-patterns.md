# Classic Drop-off Patterns

FirstClick standard catalog for dropOffPoints and timeline.

## Landing
- Value not understood
- Lack of trust
- Feeling of wrong audience

## CTA / Sign-up
- Too many fields
- Card required surprise
- Social login restriction

## Setup
- Empty screen without guidance
- Mandatory integration
- Unclear error message

## Pricing
- Unclear limits
- Seat shock
- Contact sales wall

## Dashboard
- Empty state
- Notification bombardment
- "What should I do?" uncertainty

Friction for each pattern: Landing low/med, Setup/Pricing often high.

### Depth Note Trust-2
The FirstClick analyst reads social proof, KVKK (data protection), and case study signals together in the Trust area. If there is a social proof promise in the product corpus, a contradiction with UI/KVKK is sought; if not, the [kb] general rule is applied. In persona response, case study friction is written to the timeline. Concrete suggestion: reduce social proof text to a single sentence, add visual evidence for KVKK, add micro-assurance for case study. Score impact: clarity and adoption are sensitive to trust quality; onboardingRisk increases if KVKK is missing.
