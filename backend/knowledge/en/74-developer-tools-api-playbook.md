# Developer Tools and API Sector Playbook

This file gains importance in FirstClick analysis when the sector package **developer tools / API** is selected. Each section can be retrieved as an independent RAG piece. Do not write fabricated statistics or definitive regulatory provisions.

## Scope and Business Model Context (developer tools / API)

In developer tools and API products, the buyer is usually a developer; the economic buyer comes later. Revenue can be based on usage, seat, tier, or support contracts. In FirstClick, docs quality, quickstart, API key acquisition time, and sample code are part of the first impression. If the 'Minutes to Hello World' promise conflicts with the wizard/docs, adoption drops. If there is a sales-led enterprise layer, SSO/SLA signals are sought.

This playbook customizes general SaaS rules when selected in the FirstClick sector package. The analyst does not fabricate numerical sector benchmarks; it is based on product corpus evidence. Heuristics are clearly marked and score justifications are written with citations.

## First Impression Questions (developer tools / API)

What does it do — which problem, in which stack? Is the quickstart visible? Is usage pricing clear? Rate limit/free tier? Status page? SDK languages? The skeptical developer looks for exaggerated benchmarks; the busy professional looks for long-form signup; the price-sensitive looks for hidden overage.

If the category and outcome sentence cannot be established in the first 10 seconds, clarityScore is suppressed. The CTA hierarchy should have a single primary action. If there is social proof, it should be specific; a generic logo wall may be weak.

## Onboarding and Activation (developer tools / API)

Activation: API key, first successful request, first webhook, first prod deploy. Mandatory sales calls contradict the PLG promise. If there is no copyable example in docs, friction arises. Sandbox/test mode is a strong pattern. Instead of an empty dashboard, use a 'make your first request' CTA.

Name the activation event in the product's own language. If the empty state does not show the next step, onboardingRisk increases. Make mandatory integration/form chains separate events on the timeline. If there is skip or progressive disclosure, note it as a positive signal.

## Pricing, Trust, and Compliance Warnings (developer tools / API)

Free tier limits, overage, log retention, seat+usage complexity should be transparent. 'Predictable pricing' should not conflict with hidden multipliers. If there is no self-serve path alongside enterprise 'contact us', there is PLG tension.

Unsupported percentage and guarantee claims violate citation discipline. If the KVKK/privacy link and the UI consent/purpose text conflict, trust↓. In enterprise promises, look for SSO/audit/role signals; if missing, write as a missing signal, do not give a definitive legal judgment.

## Persona Reactions (developer tools / API)

Developer: docs and examples. Skeptical: uptime claim without evidence. Busy: OAuth/signup length. Economic buyer: pricing calculator. Security reviewer: data flow diagram.

Corpus citation is mandatory in persona reactions. Do not force personas that do not fit the product. ToughQuestions should be concrete and answerable; no insults or speculation.

## Drop-off Timeline Patterns (developer tools / API)

Landing jargon → signup email verification wall → messy docs → first 401 error unclear → billing surprise. Stages: Quickstart, First call, Integrate, Prod.

Add rate and percentage. Write stage name + type of friction (confusion/friction/distrust). Week-1 silence can be an early qualitative signal.

## Evidence to Seek in Corpus (developer tools / API)

Quickstart, API ref, sample repo, pricing calculator, status, changelog, auth, rate limit, support SLA, security. Contradiction: 5 min setup vs mandatory demo; 99.99% uptime vs no status.

If no evidence, say 'not found'. In contradiction findings, place two citations side by side. Do not carry evidence from competitor sites.

## FirstClick Score Effects (developer tools / API)

Clarity: problem+stack. Adoption: time-to-first-call. OnboardingRisk: docs/auth friction. Trust: status, security, pricing predictability.

Justify the score with a one-sentence slogan. Separate clarityScore, adoptionScore, onboardingRisk, and trust effects. A promise-UI contradiction can affect multiple scores at once.

## Action Checklist (developer tools / API)

1) Place quickstart near the hero. 2) Accelerate API key issuance. 3) Copyable example. 4) Link error messages to actions. 5) Clarify free tier. 6) Status/changelog. 7) Pricing calculator. 8) Security page. 9) Sandbox. 10) Cite.

Recommendations should be actionable and prioritizable. Each recommendation should be linked to a finding. Instead of general advice like 'do better', write a concrete UI/text change.

## Time-to-First-Call Diagnosis (developer tools / API)

In developer tools, the aha moment is often the first successful API call. If there is no copyable curl/SDK example in quickstart, friction is high. If API key generation depends on a sales call, it contradicts the PLG promise. If 401/403/429 messages do not specify which header or limit is missing, onboardingRisk increases. FirstClick does not fabricate latency p95; it compares "under ms" claims with status/benchmark evidence — if absent, weak signal.

## Pricing Predictability (developer tools / API)

Usage + seat hybrid models confuse the economic buyer. If there is no pricing calculator, adoption is delayed. Free tier limits (request, log retention, seat) should be visible. "Predictable pricing" should not conflict with hidden multipliers. If there is no self-serve path alongside enterprise contact-us, note hybrid tension.

## Security and Breaking Change (developer tools / API)

Security reviewer looks for data flow, webhook signature, SOC/ISO claim (if any), and DPA link. If there is no changelog and versioning language, skeptical enterprise is delayed. If the migration guide promise is not in docs, it is a contradiction. Status page is the minimum evidence for uptime claim; if absent, "99.99%" is weak.

## Quickstart and Error Experience (developer tools / API)

In developer tools/API, the first impression is often docs + quickstart. The "Hello World in 5 minutes" promise conflicts if there is no copyable example, sandbox, or self-serve API key. If a sales call is mandatory, the PLG promise is broken. FirstClick does not measure time-to-first-call; it qualitatively writes the number of steps and blockers. If 401/403/429 messages do not specify which header, scope, or rate limit is missing, onboardingRisk increases.

If the SDK language matrix is broad in marketing but narrow in docs, distrust arises. Webhook signature verification, idempotency, and versioning language are critical signals for security/tech reviewers. If there is no breaking change policy and changelog, enterprise adoption is delayed. Status page is the minimum evidence for uptime claim; "99.99%" alone is weak — write number fabrication, claim-evidence contradiction.

## Pricing Calculator and Hybrid Sales (developer tools / API)

Usage + seat hybrid models confuse the economic buyer. If there is no calculator, adoption is delayed. Free tier limits (request, log retention, project/seat) should be visible. Overage surprise causes price-sensitive distrust. If there is no self-serve path alongside enterprise "contact sales", note hybrid tension. Security page, DPA request, and data flow diagram are sought in the corpus; if absent, note as missing signal.

## Developer Tools Score Summary

ClarityScore is sensitive to problem+stack clarity, AdoptionScore to first successful call, OnboardingRisk to auth/docs friction, Trust to status+security+predictable pricing. Timeline: Quickstart, First call, Integrate webhook, Prod, Billing. Findings are cited.

## Observability, Support, and Community (developer tools / API)

In developer adoption, sample repo, cookbook, and error search experience are as important as docs. If docs search returns empty results without suggestions, friction arises. If support SLA is in marketing but only a community forum exists, enterprise skeptical is strained. If rate limit headers and retry-after microcopy are missing, the integration team struggles. UI warnings that prevent mixing sandbox and production keys are positive trust signals.

If the partner/marketplace integration catalog promise is empty, it is a contradiction. If Terraform/provider or CLI promise is not in docs, it is missing. FirstClick does not fabricate GitHub stars or market share; it counts setup paths in the corpus.

## Security Review Checklist (developer tools / API)

Corpus checklist for security reviewer persona: data flow diagram, encryption language, subprocessors, DPA, SSO/SAML, audit log, penetration test summary (if any — if not, do not fabricate), bug bounty link, GDPR/KVKK page. Logo wall is not enough. If HIPAA or industry compliance claim is without explanation, it is weak. VPC/private link enterprise promise should be consistent between pricing and UI docs.

If the developer champion progresses self-serve but gets stuck at security review, write as a separate event on the timeline. FirstClick does not fabricate sales cycle duration.
