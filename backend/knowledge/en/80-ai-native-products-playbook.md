# AI-native Products Sector Playbook

This file gains weight in FirstClick analysis when the sector package **AI-native products** is selected. Each section can be retrieved as an independent RAG piece; each section carries the sector name within itself. Do not write fabricated statistics, conversion rates, or definitive regulatory provisions. Heuristics are explicitly marked.

## Scope and Business Model Context (AI-native Products)

In AI-native products, the core value creation or automation is based on artificial intelligence; a side feature or an AI badge is not sufficient. Revenue can be usage/credit, seat, or package-based. Exaggerated autonomy must be distinguished from assistant tool language. Hallucination, source, human oversight, and data usage are central to trust. Unsupported "10x" claims violate citation discipline. This playbook should be read together with `37-ai-trust`.

## First Impression Questions (AI-native Products)

What output is being produced? Where is human oversight? Is data being used for training? Is credit/usage clear? Is the sample output realistic? Privacy? The skeptical persona seeks sources; the busy persona wants a good first output; the non-technical persona fears prompts; the price-sensitive persona looks for credit shock.

## Onboarding and Activation (AI-native Products)

Activation: first successful output, saved template, sharing, or integration. Empty chat is weak; sample prompt is strong. Long fine-tune leads to early drop-off. Guardrail warnings should be informative.

## Pricing, Trust, and Compliance Warnings (AI-native Products)

Credit multipliers, expensive model surprises, "unlimited" throttle. Training data opt-out. KVKK (Turkish data protection law) and enterprise boundaries. Limitation language for medical/legal/financial AI. Child safety.

## Persona Reactions (AI-native Products)

Skeptical: no sources, exaggerated autonomy. Busy: slow/poor first output. Non-technical: forced prompt usage. Price-sensitive: credit shock. Security reviewer: unclear data flow. Student: lack of academic honesty warning.

## Drop-off Timeline Patterns (AI-native Products)

Hype landing → empty chat → weak output → credit paywall → privacy abandonment. Stages: First generation, Refine, Export, Paywall.

## Evidence to Seek in Corpus (AI-native Products)

Sample output, citation UI, data policy, credit pricing, model/limits, human review, security, sample prompts, admin. Contradiction: claims of never making mistakes vs. no "I don't know" statement.

## FirstClick Score Effects (AI-native Products)

Clarity: output type (not hype). Adoption: time-to-first-good-output. OnboardingRisk: empty chat/heavy setup. Trust: transparency, data, limits.

## Action Checklist (AI-native Products)

1) Output-focused hero. 2) Sample prompts. 3) Accelerate first quality output. 4) Citation. 5) Opt-out. 6) Credit transparency. 7) Limitation language. 8) Human oversight. 9) Trim exaggerated 10x claims. 10) Cite sources.

## Time-to-first-good-output (AI-native Products)

In AI-native products, the aha moment is not "account created" but the first output that is sufficient for the user. Empty chat is a weak empty state; sample prompt + template + regenerate is a strong pattern. If the first output is generic or faulty, adoption drops. FirstClick does not fabricate quality scores; it looks at ease of editing and sample quality.

Credit multipliers and expensive model surprises cause distrust for the price-sensitive. Limitation language is a mandatory heuristic for medical/legal/financial use.

## Prompt UX, Evaluation, and Cost Control (AI-native Products)

Prompt box alone is not onboarding; variables, styles, negative examples, and "why this output" explanations support adoption. If user editing (edit & regenerate) is missing, AI output forces blind trust. Batch/job queue in enterprise use requires progress and cancel options. Without cost explorer, price-sensitive users experience credit shock.

If model name, temperature/parameters, and version are hidden, skeptical users question repeatability. Prompt sharing in team workspace intersects with the permission model in the collaboration playbook. For AI aimed at children, look for age gate and safe content filter. Analyst should not repeat benchmark leadership claims without corpus evidence.

## Human-AI Collaboration Pattern (AI-native Products)

Good AI-native UX provides clear steps for human-in-the-loop: suggest → edit → approve → export. Auto-send/auto-publish as default is high risk in sensitive areas and leads to distrust. Adding sources or uncertainty indicators to output supports trust. In teams, knowing who prompted and who approved may be important for audit.

In pricing, the contradiction between "unlimited" and hidden TPM/throttle raises issues for price-sensitive+skeptical personas together. If regional model hosting is critical for enterprise security, look for corresponding docs. FirstClick does not fabricate model leaderboard rankings; match the product's own eval claim with evidence.

## User Journeys (AI-native Products)

The AI-native FirstClick journey should not be reduced to "registration → chat"; the aha is the first good output. This playbook should be read together with `37-ai-trust`.

**Individual production path:** Hero (output type) → select sample prompt/template → first generation → edit/regenerate → cite/export → (optional) registration → credit/paywall. Drop-off: hype hero, empty chat, weak first output, credit wall before aha, lack of sources.

**Team / workspace path:** Invite → permissions → shared prompt → approval/audit → admin policy. If permissions are unclear, collaboration friction occurs.

**Enterprise security path:** SSO/admin → data region/DPA docs → opt-out → model/hosting → eval. If docs are missing, it's a missing signal; do not fabricate security score.

**Automation / batch path:** Define job → queue progress → cancel → review results → human approval → send to external system. Auto-publish as default in high-risk areas leads to distrust.

Timeline: First generation, Refine, Cite/export, Paywall/credits, Admin controls, Human approval, Batch job.

## Persona Conflicts (AI-native Products)

- **Skeptical vs hype marketing:** Wants sources and limits; "autonomous worker" language causes distrust. Action: citation + limitation language.
- **Busy vs time-to-first-good-output:** Wants quick, useful output; long fine-tune or empty chat lowers adoption.
- **Non-technical vs prompt imposition:** Fear of "write a good prompt"; template/variable UI is a heuristic.
- **Price-sensitive vs usage surprise:** Cheap entry, hidden expensive model multiplier → distrust. Cost explorer / multiplier table.
- **Security reviewer vs consumer onboarding:** DPA/data flow unclear in enterprise is missing; forcing DPA on consumer flow — separate roles.
- **Student vs academic honesty:** Lack of warning is a missing signal; do not fabricate plagiarism rate.
- **Power user wanting automation vs risk:** Power user auto-sends; human approval is a necessary heuristic for trust in high-risk areas.

## Evidence and Citation Discipline (AI-native Products)

1) Do not fabricate 10x, benchmark ranking, hallucination rate, or savings percentage; cite corpus claim or do not write.
2) In contradiction between exaggerated autonomy and "I don't know"/limitation UI, provide both quotes.
3) Data training: is there opt-out or policy link; if not, mark as missing — do not speculate "probably trains".
4) Credit: model name/multiplier visibility; evaluate "unlimited" together with throttle text.
5) Medical/legal/financial: if limitation language is missing, trust↓; do not write legal compliance provisions.
6) Do not produce findings contradicting `37-ai-trust`; cite together.
7) Finding: quote + persona + stage + score + action.

## Concrete Scenarios (AI-native Products)

**Scenario A — Hype autonomy:** Hero says "replaces humans, never makes mistakes". Skeptical; trust↓; add limitation+"I don't know"+assistant tool language.

**Scenario B — Empty chat:** Only "ask something". First-timer/non-technical; First generation; onboardingRisk↑; add 5 sample prompts + template.

**Scenario C — Paywall before aha:** Credit card required before first output. Adoption↓; Paywall; heuristic is free first good output (align with corpus if promised).

**Scenario D — Hidden multiplier:** UI says "1 credit = 1 request"; expensive model is 20×. Price-sensitive; credits; show multiplier in pricing.

**Scenario E — Claim without source:** Research assistant does not show sources. Skeptical; Cite/export; citation UI.

**Scenario F — Auto-publish:** Support response auto-sent by default. Trust↓ high risk; Human approval should be default.

**Scenario G — Empty enterprise docs:** "SOC-ready" marketing, no DPA/data region. Security reviewer; Admin; missing signal or trim promise.

**Scenario H — Jargon hero:** "Multi-agent orchestration mesh". Confusion; clarity↓; output-focused hero.

## Action Descriptions (AI-native Products)

1) **Output hero:** "Produces X" + sample output visual/text; trim exaggerated autonomy.
2) **Sample prompt pack:** 5+ role-based templates; variable fields.
3) **Edit loop:** Edit → regenerate → version history (if available).
4) **Citation:** Source list or "no source / not sure" state.
5) **Opt-out:** Training data control + policy link.
6) **Credit transparency:** Model×multiplier table; throttle should not contradict "unlimited".
7) **Limitation language:** Warning + human guidance in high-risk categories.
8) **Human-in-the-loop:** Suggest → edit → approve → export; auto-send is opt-in.
9) **Cost explorer:** Estimated credit consumption before job.
10) **Enterprise package:** Admin, data region, DPA link — if missing, write missing signal.
11) **Child safety:** Look for age gate / safe filter signal.
