# Productivity and Collaboration Sector Playbook

This file gains weight in FirstClick analysis when the sector package **productivity / collaboration** is selected. Each section can be retrieved as an independent RAG piece; each section carries the sector name within itself. Do not write fabricated statistics, conversion rates, or definitive regulatory provisions. Heuristics are explicitly marked.

## Scope and Business Model Context (productivity / collaboration)

Productivity and collaboration products can be notes, tasks, documents, whiteboards, meetings, asynchronous communication, or all-in-one workspaces. Revenue comes from seat, usage, or workspace plans. Value usually increases with the team; the invite loop is part of activation. If the pitch says "team productivity," single-user onboarding may be insufficient. If FirstClick sees competitor names, it looks for proof of differentiation; it does not make speculative comparisons.

Tension between B2B purchasing and PLG is common: while there is a self-serve trial, SSO/admin promise may be missing. Busy-professional wants a quick setup process. If the migration promise contradicts the empty state, onboardingRisk increases. If the all-in-one promise opens every module on the first screen, confusion risk rises.

## First Impression Questions (productivity / collaboration)

Who is it for — individual or team? What business outcome (fewer meetings, single source of truth, faster decisions)? Are there templates? Is the import promise realistic? Is the price per seat/guest? Offline/mobile promise? Good hero heuristic: "The only workspace for small teams — your first board in 2 minutes." Weak: "OS for modern work." Skeptical reacts to unproven productivity percentages; price-sensitive reacts to guest surprises.

## Onboarding and Activation (productivity / collaboration)

Activation events: first document/board, first comment, first invite, first integration. Sample content or templates are strong patterns. Mandatory team creation pushes away individual users. Invite should be early but not blocking. Empty state should carry a template gallery and a single CTA instead of a "blank page." If the import wizard fails, write Integrate friction to the timeline; do not fabricate success rates.

## Pricing, Trust, and Compliance Warnings (productivity / collaboration)

If the distinction between guest and paid seat is unclear, price-sensitive distrust arises. "Unlimited" should not contradict with footnoted limits. Public link security and default external sharing are critical for the security reviewer. KVKK, data region, and admin audit log are sought in enterprise promises; if missing, it's a negative signal — no legal provision. If paywall templates are locked before the aha moment, adoption↓.

## Persona Reactions (productivity / collaboration)

Busy-professional: long setup and notification noise. Skeptical: unproven "productivity %X." Non-technical: complex information architecture. Price-sensitive: guest fee surprise. Student: unclear education plan. Security reviewer: default public link. Corpus citation is mandatory in persona reactions.

## Drop-off Timeline Patterns (productivity / collaboration)

Heuristic: Unclear positioning on landing → empty workspace → mandatory invite → failed import → paywall template lock → notification fatigue. Stages: Setup, First object, Invite, Integrate, Paywall. Do not write rates.

## Evidence to Seek in Corpus (productivity / collaboration)

Template gallery, invite UI, permission/public link, import, pricing seat/guest, admin/SSO, empty state, mobile, notification settings, migration guide. Contradictions: "Setup in 2 minutes" vs 8 steps; "for teams" vs no invite; "secure sharing" vs default public.

## FirstClick Score Effects (productivity / collaboration)

ClarityScore: clarity of individual/team and outcome. AdoptionScore: template + invite + fair paywall. OnboardingRisk: empty workspace and heavy import. Trust: sharing security and admin/KVKK. Promise-UI contradiction affects multiple scores.

## Action Checklist (productivity / collaboration)

1) Clarify team/individual. 2) Deliver aha with a template. 3) Make invite early but optional. 4) Explain guest/seat. 5) Simplify import path. 6) Move paywall after value. 7) Clarify permission microcopy. 8) Verify SSO promise. 9) Place CTA in empty state. 10) Lock findings with citation.

## Aha with Template and Migration (productivity / collaboration)

In collaboration products, empty workspace is the most frequent source of onboardingRisk. If the template gallery is not role/sector-based, busy-professional delays in finding value. If the import (docs, CSV, Trello, etc.) promise fails or is left incomplete, write Integrate friction to the timeline. FirstClick does not fabricate migration success rates; it reads import steps and error copy in the UI.

## Invite and Permission Model (productivity / collaboration)

Team value does not fully form without invite; however, mandatory invite pushes away individual users. If the distinction between guest and paid seat is unclear on the pricing page, price-sensitive distrust arises. Default public link can be a red flag for the security reviewer. If the permission microcopy ("everyone can edit") is unclear, skeptical toughQuestions arise.

## IA Overload (productivity / collaboration)

If the all-in-one promise opens wiki+task+chat+CRM on day one, confusion arises. Progressive disclosure heuristic: 2–3 primary objects in the first session. If notification defaults are aggressive, retention risk is noted qualitatively; no churn percentage. If SSO/admin promise is in the enterprise plan, look for its counterpart in UI/docs.

## Template, Import, and Empty State Depth (productivity / collaboration)

In collaboration products, empty workspace is the most common source of onboardingRisk. If the template gallery is not separated by role or workflow, busy-professional delays in finding value. If the "import" promise has weak error copy or supported sources are fewer than marketing claims, it's a contradiction. FirstClick does not fabricate migration success rates; it reads import steps and resulting empty state. If there is a sample workspace (demo data), it's a positive signal.

In all-in-one products, opening wiki+task+chat+CRM at once in the first session creates confusion. Progressive disclosure heuristic: 2–3 primary objects on the first day. 15 empty sections in the sidebar is a maze for non-technical personas. If search is missing or poor, knowledge worker adoption weakens — search quality is not measured, only presence/absence and empty result state are noted.

## Invite, Guest, and Security (productivity / collaboration)

Team value increases with invite; mandatory invite pushes away individual users. If the distinction between guest and paid seat is unclear on the pricing page, price-sensitive distrust arises. Default public link can be a red flag for the security reviewer. Unclear "everyone can edit" microcopy produces skeptical toughQuestions. If SSO, SCIM, audit log are mentioned in the enterprise promise, look for their counterpart in UI/docs. If notification defaults are aggressive, retention risk is written qualitatively; no churn percentage.

## Paywall and Package Fairness (productivity / collaboration)

If templates or basic sharing are locked before the aha moment, adoption↓. If "unlimited" storage/version history is limited by footnotes, it's a contradiction. If education/nonprofit plan is unclear, student persona objects. Analyst does not fabricate competitor pricing tables; reads product pricing language.

## Productivity Score Summary

Clarity is sensitive to individual/team clarity, Adoption to template+invite+fair paywall, OnboardingRisk to empty workspace/import, Trust to sharing security and admin. Timeline: Setup, First object, Invite, Integrate, Paywall.

## Meeting, Asynchronous, and Focus Conflicts (productivity / collaboration)

The meeting recording/summary promise at the AI-native intersection should not carry exaggerated autonomy; a correction path should be sought for incorrect summaries. Asynchronous comment and @mention noise is a retention risk for busy-professionals — read the default notification set qualitatively. If the offline editing promise lacks a conflict resolution UI, it's a risk; look for contradictions. If the mobile app's "full feature" claim contradicts with missing editor, adoption↓.

If education, nonprofit, or startup plans are unclear, student/price-sensitive personas object. Admin's user deletion/data export path can be associated with KVKK deletion requests; no legal provision, check for UI presence. If there is a competitor migration checklist, it's positive; if not, do not count the migration promise as weak, just note the lack of signal.

## Workspace Admin and Data Lifecycle (productivity / collaboration)

Admin flows for user invite, role, content ownership transfer, and offboarding (employee exit) are critical for enterprise adoption. If there is no export path for "your data is yours," it's a contradiction. Trash/version history limits should not be hidden in pricing footnotes. Time limit for external guest access can be a positive security signal. Analyst does not fabricate ISO certification; if claimed, look for a proof page.

For busy-professionals, if the "what should I do today" home empty state does not offer a template or incoming @mention list, it's weak. The claim of keyboardless mobile editing should not contradict with desktop-only features.

## Diagnostic Question Bank (productivity / collaboration)

1) What object should the user create in the first session? 2) Are templates role-based? 3) Is invite blocking? 4) Is guest paid? 5) What is the default for public link? 6) Which sources does import support and what is the error language? 7) Where is SSO promised and where is it missing? 8) Are notification defaults aggressive? 9) Is there export/offboarding? 10) What value does the paywall lock? If there is no answer to these questions, write "no signal found"; do not fill with sector assumptions.
