# Real Estate Sector Playbook

This file gains importance in FirstClick analysis when the sector package **real estate** is selected. Each section can be retrieved as an independent RAG piece; each section carries the sector name within itself. No fabricated statistics, conversion rates, or definitive regulatory provisions are written. Heuristics are explicitly marked.

## Scope and Business Model Context (real estate)

Real estate products may include listing portals, intermediary CRMs, virtual tours, mortgage linking, proptech management, or rental operations. Revenue may come from listing fees, leads, subscriptions, or commissions. Trust (verified/up-to-date listings, agent identity) and search quality stand out. If there is a buyer–seller/tenant–landlord duality, role separation is required. "Guaranteed return" generates distrust.

## First Impression Questions (real estate)

Is it for sale/rent/project? Is the geography honest? Is the listing up to date? Is it an agency or owner? Who pays the fee? Mortgage intermediary? Skeptical about fake listings; price-sensitive about maintenance fees; busy users want fast filters.

## Onboarding and Activation (real estate)

Buyer: saved search, message, appointment. Agent: listing, lead response. Heavy agent registration causes early drop-off. An empty map creates a perception of weak liquidity — no fabricated rates.

## Price, Trust, and Compliance Warnings (real estate)

Transparency of maintenance fees and additional costs. Badge meaning. KVKK (data privacy) lead sharing. Exaggerated ROI is a red flag. Listing renewal fees must be clear.

## Persona Reactions (real estate)

First-timer: fear of the process. Skeptical: stock photo. Busy: unreturned form. Price-sensitive: hidden commission. Agent: lead quality is unclear.

## Drop-off Timeline Patterns (real estate)

Filter confusion → outdated listing → communication requiring membership → unanswered lead. Stages: Search, Listing, Contact, Agent onboarding.

## Evidence to Search in Corpus (real estate)

Filter, map, listing date, verification, fee, mortgage calculator, agent profile, virtual tour, KVKK, floor plan.

## FirstClick Score Effects (real estate)

Clarity: transaction type + geography. Adoption: search → contact. OnboardingRisk: heavy agent setup. Trust: up-to-dateness + verification.

## Action Checklist (real estate)

1) For sale/rent is clear. 2) Listing date. 3) Maintenance/additional cost. 4) Verification definition. 5) Reduce communication friction. 6) Trim ROI exaggeration. 7) Empty map management. 8) Agent response path. 9) KVKK. 10) Quote.

## Listing Trust and Up-to-dateness (real estate)

In real estate, trust largely depends on listing up-to-dateness, duplicate listing control, and the meaning of the verification badge. If the "new" label is undated, it's weak. Stock photo suspicion generates skeptical toughQuestions. FirstClick does not fabricate fake listing rates; it looks at the date/verification UI.

## Search → Communication Friction (real estate)

Mandatory membership + mandatory phone for every message pushes away busy buyers. Progressive contact heuristic. If maintenance and additional costs are not on the PDP, price-sensitive users distrust. Investment ROI guarantee works like fintech exaggeration — trim or prove.

## Agent / Owner Onboarding (real estate)

## Rental Operations and Proptech Management (real estate)

In rental-focused products, contract, deposit, maintenance request, and payment reminder affect trust after activation. The "digital contract" promise contradicts if there is no signature flow. In site/apartment management, the resident app and manager panel should not be mixed. Maintenance debt display requires a purpose text balancing KVKK/transparency; no legal provision.

In new project (off-plan) sales, delivery date, building permit, and payment plan up-to-dateness are the backbone of trust. If the virtual tour promise contradicts with low-quality panorama, adoption weakens. If appraisal/mortgage integration is third-party, the brand relationship must be clearly stated.

## Map, Neighborhood, and Decision Support (real estate)

Neighborhood score, school, and transportation layers are decision support; if there is no methodology, the skeptical persona asks "what is being measured?". FirstClick does not measure neighborhood quality. The heat map promise should not contradict with empty pins. If there is no favorite comparison table (price per m², maintenance, room), busy buyers face friction. Mortgage calculator assumptions (interest, term) must be visible; do not write financial advice.

If automatic lead assignment rules are unclear in agent CRM, there is internal friction. Bulk listing entry (XML/portal sync) promise is weak without error reporting. Analyst does not fabricate portal market share.

## User Journeys (real estate)

In real estate, buyer/tenant, seller/owner, agent, and (if any) manager journeys are separated.

**Buyer / tenant journey:** Select geography+transaction type → filter/map → listing detail (date, maintenance, verification) → contact (progressive) → appointment/message → (optional) mortgage calculator. Drop-off: filter confusion, outdated listing, membership+phone wall, unanswered form, hidden maintenance.

**Agent journey:** Registration/verification → listing entry or XML sync → lead inbox → response → CRM. Drop-off: heavy KYC, unclear lead quality, no sync error report.

**Owner journey:** Create listing → photo/plan → publish → message. Should not mix with agent flow.

**Rental operations / proptech:** Contract → deposit → maintenance request → maintenance/payment. "Digital contract" contradicts if there is no signature flow.

**Off-plan project:** Payment plan → delivery date → permit info up-to-dateness.

Timeline: Search, Listing detail, Contact, Agent onboarding, Financing CTA, Lease ops, Project update.

## Trust and Drop-off Signal Matrix (real estate)

Trust↑: listing update date, verification badge definition, maintenance/additional cost, agent profile, readable floor plan, response path/SLA text (no rate), KVKK lead purpose, visible mortgage assumptions, virtual tour quality matches promise.

Trust↓ / drop-off: undated "new", stock photo–facade mismatch, guaranteed return, hidden commission, membership required for every message, empty map weak liquidity perception (no fabricated rate), unanswered lead, outdated project delivery date, neighborhood score without methodology.

Chain: filter confusion → outdated listing → communication wall → ghosting → ROI exaggeration.

## Persona Conflicts (real estate)

- **Busy buyer vs mandatory phone+membership:** Wants to ask quickly; lead form at every step lowers adoption. Progressive contact.
- **Skeptical vs stock photo / undated badge:** Fake listing concern; FirstClick does not fabricate rates, looks at date/verification UI.
- **Price-sensitive vs hidden maintenance/commission:** If cost is missing on PDP, distrust.
- **First-timer vs process uncertainty:** "How to proceed" gap; checklist heuristic — no legal process provision.
- **Agent economic buyer vs lead quality:** If "quality lead" promise is undefined, objection; quality score is not fabricated.
- **Buyer "ask now" vs agent "qualified lead":** Mandatory phone can tire both sides; staged communication.
- **Manager vs resident app:** If mixed in the same menu, clarity↓.

## Action Descriptions (real estate)

1) **Transaction type clarity:** For sale/rent/project distinction in hero and filter.
2) **Listing date mandatory field:** "Last update" visible; remove undated "new".
3) **Verification glossary:** Badge tooltip — which of identity, deed, photo, agent license, etc. (as corpus states).

5) **Progressive contact:** Message first, phone later or optional.
6) **Response path:** "Response process" explanation; do not fabricate SLA percentage.

9) **Mortgage CTA:** Third-party relationship + calculator assumptions.
10) **Lease ops:** Align signature flow or promise; separate resident/manager.
