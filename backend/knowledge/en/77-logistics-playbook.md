# Logistics Sector Playbook

This file gains weight in FirstClick analysis when the sector package **logistics** is selected. Each section can be retrieved as an independent RAG piece; each section carries the sector name within itself. No fabricated statistics, conversion rates, or definitive regulatory provisions are written. Heuristics are clearly marked.

## Scope and Business Model Context (logistics)

Logistics products may include cargo tracking, carrier matching, fleet, warehouse WMS, delivery slot, or B2B freight. Revenue may be transaction-based, subscription, or commission. The promise of operational reliability (SLA, ETA, exception) should be visible in the UI. If there is a carrier–shipper two-sidedness, role separation is required. If consumer tracking is mixed with enterprise TMS, clarity decreases.

## First Impression Questions (logistics)

Who — shipper, carrier, consignee, warehouse? Outcome: cost, time, visibility? Is integration mandatory? How is pricing calculated? Is there live ETA and exception management? Busy ops want speed; skeptical users question SLA claims; field non-technical users want simple mobile.

## Onboarding and Activation (logistics)

Activation: first shipment, label, tracking link, route, or sync. Mandatory ERP can cause early drop-off; CSV/manual path is a heuristic. Instead of an empty map, show a sample shipment. If there is no price calculator, confusion arises.

## Price, Trust, and Compliance Warnings (logistics)

Weight/zone matrices require a calculator. "Everywhere" should not contradict with exceptions. Address/phone sharing is in the context of KVKK. Dangerous goods restrictions should be visible. Hidden extra fees cause distrust.

## Persona Reactions (logistics)

Busy ops: too many clicks. Skeptical: ETA deviation without communication. Price-sensitive: extra fees. Field non-technical: small buttons/jargon. Economic buyer: proof of savings — no fabricated percentages.

## Drop-off Timeline Patterns (logistics)

Unclear role → heavy setup → integration wall → price uncertainty → no exception. Stages: Setup, First shipment, Tracking, Exception.

## Evidence to Search for in Corpus (logistics)

Role CTA, calculator, shipment form, tracking, ETA, exception, integration, field mobile, SLA, KVKK. Contradiction: instant price vs "wait for quote" as the only path.

## FirstClick Score Effects (logistics)

Clarity: role+outcome. Adoption: first shipment. OnboardingRisk: integration. Trust: ETA/SLA and extra fee transparency.

## Action Checklist (logistics)

1) Clarify role. 2) Manual first shipment. 3) Calculator. 4) Tracking link as aha. 5) Exception UI. 6) Extra fee transparency. 7) Simple field mobile. 8) Postpone integration. 9) KVKK. 10) Cite.

## First Shipment Activation (logistics)

In logistics, the aha is usually label/shipment creation or sharing a tracking link. Mandatory ERP integration can cause early drop-off; CSV/manual path is a heuristic. If there is no price calculator, weight/zone complexity creates confusion. "Delivery everywhere" should not contradict with an exception list. FirstClick does not fabricate delivery success rates.

## Visibility and Exception Management (logistics)

If the tracking screen only says "in transit," operational realism is weak. Exception (delay, undeliverable) should show reason + next step. SLA/ETA claims without deviation communication in the UI produce skeptical distrust. If there is a POD photo, the privacy warning should be transient.

## Field Mobile and Role Separation (logistics)

Field personnel behave like non-technical personas: large CTA, little jargon. If there is an offline promise, look for queue signal. If shipper–carrier–warehouse roles are mixed, clarity↓. Freight and last mile should not be mixed in the same hero.

If there is an offline promise, look for queue/sync signal. If freight quote flow and last mile slot/proof of delivery are mixed in the same hero, clarity↓.

## Multi-Carrier, Customs, and B2B Freight (logistics)

If multi-carrier price comparison does not explain the sorting logic (price, time, reliability), skeptical confusion occurs. Customs/international shipment promises are weak without a document checklist; the analyst does not interpret customs law. In B2B freight, confusion between quote, contract price, and spot price requires pricing clarity. Invoice and cost center fields may be critical for the economic buyer.

In fleet management, the driver mobile shift and stop list should be simple. If dangerous goods or cold chain restrictions are not visible, operational risk communication is lacking. Insurance add-on price should not be a surprise at checkout.

## Exception Communication and Customer Experience (logistics)

If the consignee SMS/email tracking language is jargon-heavy, non-technical confusion arises. If there is a promise of proactive status update on delay but no automation, contradiction. If delivery slot selection is promised as integrated with e-commerce checkout but missing, incomplete. If return logistics (reverse) is a separate flow, empty state and label creation aha should be separately defined. Analyst does not fabricate NPS.

If in warehouse WMS, counting, placement, and picking roles are mixed in the menu, there is a risk of field error — recommend UI simplification. The promise of multi-warehouse stock visibility contradicts with a single warehouse UI.

## User Journeys (logistics)

In logistics, the FirstClick journey should be separated by role. A single "user registration → dashboard" summary is insufficient.

**Shipper path:** Role selection → price/calculator or quote → shipment creation (manual/CSV) → label → tracking link sharing → exception notification → billing. Drop-off: unclear role, no calculator, mandatory ERP, surprise extra fee, empty exception screen.

**Carrier / driver path:** Invitation or registration → job/route acceptance → mobile stop list → POD → payment/entitlement. Drop-off: small CTA, jargon, unfulfilled offline promise, unclear entitlement.

**Consignee path:** SMS/email link → tracking status → slot/rescheduling → delivery/signature. Drop-off: jargon-heavy status, silence in delay, promised slot missing.

**Warehouse / WMS path:** Role (counting, placement, picking) → task list → verification. Menu confusion is a field error risk — do not fabricate error rate.

**Freight / B2B path:** RFQ → spot vs contract price → approval → booking → document. Quote uncertainty is economic buyer friction.

Timeline labels: Setup, First shipment, Tracking, Exception, Billing, Driver mobile, Warehouse task. Freight and last mile should not be mixed in the same finding.

## Trust and Drop-off Signal Matrix (logistics)

Trust↑ candidates: live ETA + deviation communication, exception reason+next step, extra fee breakdown, SLA text UI counterpart, calculator, manual first shipment, POD privacy warning, dangerous goods/cold chain restriction visibility.

Trust↓ / drop-off: "everywhere" + exception list contradiction, hidden extra fee, only "in transit" tracking, integration wall, field jargon, customs promise without documents, surprise insurance price, missing reverse logistics empty state. Delivery success rate or NPS is not fabricated.

Drop-off chain heuristic: unclear role → heavy setup → mandatory integration → price uncertainty → no exception → billing surprise. Each link requires separate evidence.

## Persona Conflicts (logistics)

- **Busy ops vs IT integration:** Ops wants first shipment; IT wants ERP sync. Heuristic: CSV/manual first shipment, postpone integration — do not claim "integration unnecessary."
- **Skeptical vs marketing SLA:** Marketing says "on-time delivery"; if UI lacks deviation communication, distrust. Quote both texts.
- **Price-sensitive vs accessorial fees:** Base price low, fuel/remote area/waiting hidden causes distrust. Calculator or checkout breakdown.
- **Field non-technical vs desktop TMS:** Small button, too many fields, English jargon → adoption↓. Large CTA, few fields, local language heuristic.
- **Economic buyer vs savings claim:** "Reduce cost" without proof triggers toughQuestions; fabricated savings percentage not allowed.
- **Consignee vs shipper notification:** Consignee wants simple status; shipper wants operational detail. SMS language should be simple for consignee.

Do not flatten conflict with a single score; write findings labeled by persona.

## Evidence and Citation Discipline (logistics)

1) Do not fabricate KPI, on-time %, damage rate, cost savings.
2) Evaluate ETA/SLA claim together with absence of exception UI; quote the claim.
3) In contradiction between "instant price" and "wait for quote," indicate both paths.
4) For customs/dangerous goods, do not interpret legal matters; check for checklist or warning UI.
5) For offline promise, look for queue/sync signal; if absent, note missing signal.
6) Finding: quote + role + stage + score + action.

## Action Descriptions (logistics)

1) **Clarify role:** Primary CTA for one role; other roles as secondary links.
2) **Manual first shipment:** 3–5 field form or CSV template; integration "later."
3) **Calculator package:** Weight, volume, zone, extra service; label "quote" alternative.
4) **Tracking realism:** Status + reason + next step + ETA deviation communication.
5) **Field mobile:** Large touch targets, little jargon, offline queue indicator (if promised).
6) **Fee transparency:** List accessorials before checkout; insurance add-on price early.
7) **Reverse aha:** Separate empty state for return label creation.
8) **WMS simplification:** Separate task view for counting/placement/picking.

## Edge Cases (logistics)

- Multi-warehouse stock promise should not contradict with single warehouse UI.
- Fleet shift: stop list in driver mobile should be simple; do not write fatigue/regulation provision.
- Consignee slot promise missing in e-commerce checkout is a missing signal.
- POD photo: temporary privacy warning; no definitive KVKK provision.
